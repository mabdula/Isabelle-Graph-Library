bench_networkx -- NetworkX 3.4.2 single_source_dijkstra(G, s, target=t), column "networkx"

USAGE
  bench_networkx --source <s> --target <t> [--query <id>] [--tag <text>] [--repeats <k>] [--mem-gb <g>] <instance.gr>
  bench_networkx --header
  --mem-gb caps the address space (RLIMIT_AS); the campaign passed --mem-gb 45.

WHAT IS TIMED
  nx.single_source_dijkstra(g, s, target=t, weight="weight") alone, which
  stops when t is settled.  The DiGraph is filled arc by arc OUTSIDE the clock
  (build_ms), after reading the file (parse_ms) and collapsing parallel arcs to
  the cheapest (dedup_ms; add_edge would otherwise keep the last one).  One
  trivial call is made before the clock so the lazy module import is not
  timed.  Clock: process CPU time (getrusage).

COLUMNS (one CSV row per run; --header prints the header line alone)

  instance      base name of the .gr file
  nodes, arcs   from its problem line
  query         the id passed with --query (0 if none)
  source,target the pair passed on the command line, DIMACS ids 1..n
  repeat        1 (the campaign ran every repeat in its own process, so this is
                always 1 in the raw data of the paper appendix; --repeats k prints k rows)
  status        OPTIMAL      a path was found and its ends are (source, target)
                UNREACHABLE  the solver finished and reported no path
                BAD_PATH     a path came back whose ends are not (source, target)
                MEMORY       (Python drivers) the address-space cap was hit
  reached       1 if a path was found, else 0
  hops          number of arcs on the returned path
  dist          its length, the sum of the arc weights (-1 if unreachable)
  cpu_ms        THE MEASUREMENT: CPU time between the two clock readings
  cpu_usr_ms, cpu_sys_ms   its user/system split
  proc_ms       whole-process CPU time over the same window (equal to cpu_ms
                for native programs; for JVM programs it also counts the JIT
                compiler threads and is a diagnostic, not the measurement)
  wall_ms       wall-clock time over the same window; nothing is derived from it
  parse_ms      CPU time spent reading the file, OUTSIDE the clock
  dedup_ms      CPU time spent collapsing parallel arcs, OUTSIDE the clock
                (0.000 unless the library cannot hold parallel arcs)
  build_ms      CPU time spent marshalling the arrays into the library's input
                format, OUTSIDE the clock (0.000 for the exports)
  tag           free text copied from --tag (the campaign put "<family>;rep=<k>" there)
  (this program prints no clock_build_ms/clock_solve_ms columns: nothing is
  built inside the clock)

EXAMPLE
  Square-n.10.0.gr,1024,3968,0,14,787,1,OPTIMAL,1,8,3418,<cpu_ms>,<usr>,<sys>,<proc>,<wall>,<parse_ms>,<dedup_ms>,<build_ms>,Square-n;rep=1

The raw rows of the paper appendix (paper_results/dijkstra_results.zip, <column>/raw/<family>.csv) carry
two further columns appended by the campaign runner, inferred_from and core,
which the program itself does not print.
