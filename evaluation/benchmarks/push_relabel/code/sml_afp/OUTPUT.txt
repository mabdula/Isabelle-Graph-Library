bench_sml_afp -- the AFP FIFO push-relabel export (Lammich and Sefidgar, Prpu_Maxflow) in Standard ML (MLton), column "SML AFP" (sml_afp)

USAGE
  bench_sml_afp [--source <s> --target <t>] [--tag <text>] [--repeats <k>] <instance.max>
  bench_sml_afp --header
  variant column: "afp_fifo"

WHAT IS TIMED
  One call of fifo_push_relabel_impl, the whole verified program: it
  tabulates its own dense n x n residual capacity matrix from the capacity
  function, saturates the source arcs, initialises labels, counters and the
  FIFO queue, then discharges to exhaustion (a maximum flow).  OUTSIDE the
  clock, reported in build_ms: turning the arc list into the adjacency map
  and capacity lookup the entry point takes (code/sml_afp/csr.sml; parallel
  arcs are summed there).  Clock: process CPU time (getrusage).

  LIMITS SEEN IN THE TABLES.  The export indexes its n x n array with MLton's
  default 32-bit Int, which overflows at n = 65,538 ("unhandled exception:
  Overflow", recorded as ERROR in the raw rows and OVF in the paper).  Its
  network model forbids antiparallel arcs, which genrmf produces, so the
  rmf-long family was not run (NOT_APPLICABLE in the raw rows, n/a in the paper).

COLUMNS (one CSV row per run; --header prints the header line alone)

  instance      base name of the .max file
  nodes, arcs   from its problem line
  variant       the solver/variant name this program writes (see below)
  source,target the source and the sink, DIMACS ids 1..n, from the file's
                `n <id> s` / `n <id> t` lines unless given with --source/--target
  repeat        1 (every repeat of the campaign was its own process; the
                runner stamped the repeat number, which for the seeded
                families is the seed, into this field afterwards)
  status        OK             the returned arc flows are a flow: within capacity,
                               conserved at every vertex but the two ends, and
                               the ends balance
                OVER_CAPACITY, NOT_A_FLOW, UNBALANCED_ENDS, VALUE_MISMATCH
                               the check failed (never seen in the rows of the paper appendix)
  flow_value    the maximum flow value, summed after the clock as a cross-check
  cpu_ms        THE MEASUREMENT: whole-process CPU time (user + system)
                between the two clock readings
  cpu_usr_ms, cpu_sys_ms   its split
  thread_ms     the solver thread's CPU time over the same window (equal to
                cpu_ms for single-threaded native programs; for the JVM it
                drops garbage collection and is kept only to show the gap)
  wall_ms       wall-clock time over the same window; nothing is derived from it
  parse_ms      CPU time spent reading the file, OUTSIDE the clock
  dedup_ms      CPU time spent collapsing parallel arcs, OUTSIDE the clock
  build_ms      CPU time spent building the library's input structure, OUTSIDE
                the clock (0.000 for the exports and hi_pr)
  tag           free text copied from --tag; the campaign wrote
                "island=<cores>;repeat=<k>;seed=<s>" and some programs append
                their own notes (see each OUTPUT.txt)

EXAMPLE
  wash-rlg-long-128-32.max,4098,12160,afp_fifo,1,4098,1,OK,978552,313.065,261.417,51.648,313.065,313.124,2.118,0.000,2.076,island=4-7;repeat=1;seed=1

The raw rows of the paper appendix (paper_results/push_relabel_results.zip,
<column>/raw/<family>.csv) are these rows cut down to the columns the tables
use; the full rows are in the campaign directories of the study.
