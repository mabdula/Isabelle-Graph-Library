INSTANCES OF THE HUNGARIAN METHOD STUDY -- where every graph came from
=====================================================================

Three families of the 13th DIMACS Implementation Challenge, Network Flows
2.0 ("Assignment Problem Instances and Generators"), ten instances per size
(generator seeds 1..10), DIMACS .asn format (p asn <nodes> <arcs>; n <v>
marks the X side; a <x> <y> <cost>).  No instance is distributed here;
every file is regenerated byte for byte by the generators in generators/
and checked against MD5SUM_instances.txt (150 files, the ones behind
Tables 22 to 24).

HOW TO OBTAIN
  Generators  ../setup_instances.sh fetches assign.c, dcube.c, twocost.a and geomasn.a (and the
              depository's readme) from the First DIMACS Challenge depository at
              archive.dimacs.rutgers.edu (URLs and md5 in the script) and makes the
              patched copies that compile today; `make' in generators/ builds them.
  Instances   not distributed: regenerate them with generators/gen_instances.sh and
              gen_geometric.sh for the
              sizes and seeds listed in seeds/<family>.txt and compare with
              MD5SUM_instances.txt.

1. low-cost   assign.c with nodes N, sources N/2, degree 2 log2 N, maxcost
              100, seed K; N = 2^11..2^15, m = N log2 N.  Table 22.
2. two-cost   the same assign.c output piped through the DIMACS awk filter
              twocost.a; the filter's banner is glued to the problem line
              and the script splits it back (see gen_instances.sh).  Table 23.
3. geometric  dcube.c with nodes N, dimension 2, maxloc 1000000, seed K,
              piped through geomasn.a: N points in [1,10^6]^2, first N/2
              left, last N/2 right, every left-right pair joined at the
              truncated Euclidean distance -- complete bipartite, m = N^2/4;
              N = 2^8..2^12.  geomasn.a writes arc lines with the letter e,
              rewritten to a (see gen_geometric.sh).  Table 24.

GENERATORS  generators/assign.c, twocost.a, dcube.c, geomasn.a, readme are
            fetched by ../setup_instances.sh (they are not in the package) from the
            First DIMACS Challenge depository
            (https://archive.dimacs.rutgers.edu/pub/netflow/generators/network/
            for assign.c, twocost.a, geomasn.a; .../generators/matching/dcube.c),
            md5 98bba042619c8f1c1664b74631958a86 (assign.c),
            f51724183524b2a2d7dbb19bd1b32dce (twocost.a),
            3b1fcbbb4e1689444c20954fa7042e28 (dcube.c),
            e390c3b59ba217ce8c1e5f2112c5b1ad (geomasn.a).
            generators/build/assign_patched.c and dcube_patched.c, which setup_instances.sh
            makes with generators/assign.c.patch and dcube.c.patch, are what
            was compiled: K&R C made to build on x86-64 (headers, a declared
            `cmd', exit(1), MAXNODES 1048576, %ld for the seed); `diff'
            against the pristine files shows the whole change.  `make' in
            generators/ builds them with cc -O2.
            gen_instances.sh and gen_geometric.sh are the study's scripts AS
            RUN, with their three path variables made relative (noted in a
            comment at the top of each); they validate every file they write
            (problem line present, arc count as promised) because both
            generators exit with a junk status.

SEEDS       seeds/low-cost.txt, two-cost.txt, geometric.txt list, for every
            instance of the tables, the exact generator input and pipeline.
            The first comment lines of each .asn repeat the parameters.

CHECKING    MD5SUM_instances.txt: md5, size and path of every .asn file the
            campaigns read for the tables.  Example:
              ./gen_instances.sh --nodes 2048 --seeds 1 && md5sum out/low-cost/low-cost_n2048_s1.asn
            must print 3ff54195b3017fc75fdf39efd4ddf78e.
