bench_jgrapht_mwbm_hashgraph -- JGraphT 1.5.3 MaximumWeightBipartiteMatching on SimpleWeightedGraph built outside the clock, column "jgrapht_mwbm_hashgraph" (paper: JGraphT MWBM hash)

USAGE
  [JAVA_HOME=<jdk>] bench_jgrapht_mwbm_hashgraph [--csv] [--tag <text>] <instance.asn>
  (the launcher fixes --solver mwbm)

WHAT IS TIMED
  The matcher's constructor and getMatching() on a SimpleWeightedGraph (an
  object per edge, hash maps around it) that was filled edge by edge OUTSIDE
  the clock; ../jgrapht_mwbm measures the
  same library on jgrapht-opt's CSR graph built inside the clock (column
  jgrapht_mwbm_csr).  The matcher MAXIMISES, so
  arcs enter at |X|*cmax + 1 - cost, and the reported cost is converted back.
  Before the clock a small synthetic instance is solved with the same matcher
  so the JIT has compiled it.  Clock: the solver THREAD's CPU time
  (ThreadMXBean, user + system), NOT including the garbage collector's pause
  time.  JVM flags: -XX:ActiveProcessorCount=1 -XX:+UseSerialGC -Xmx24g.

COLUMNS (one CSV row per run with --csv; without it a human-readable block)

  instance      base name of the .asn file
  nodes, arcs   from its problem line
  left, right   |X| and |Y|
  theta, theta_frac
                always 0 and 0.000: they belong to the export's shortcut and
                are kept so every solver's rows have the same shape
  status        OPTIMAL, NO_PERFECT_MATCHING, or ERROR_<code> / TIMEOUT
  matched       number of matched left vertices (= |X| when OPTIMAL)
  cost          the weight of the matching, minimised
  cpu_ms        THE MEASUREMENT: CPU time between the two clock readings
  cpu_usr_ms, cpu_sys_ms   its user/system split
  wall_ms       wall-clock time over the same window; nothing is derived from it
  tag           free text copied from --tag (the campaign put "<family>;rep=<k>" there)

EXAMPLE (the sweep's raw row for low-cost_n2048_s1.asn)
  instance,nodes,arcs,left,right,theta,theta_frac,status,matched,cost,cpu_ms,cpu_usr_ms,cpu_sys_ms,wall_ms,tag
  low-cost_n2048_s1.asn,2048,22528,1024,1024,0,0.000,OPTIMAL,1024,7920,254.872,190.000,64.872,520.310,low-cost;mwbm;rep=1

The published raw rows (published_results/hungarian_results.zip,
<column>/<family>.csv) carry two further columns appended by the campaign
runner, inferred_from and core, which the program itself does not print.
