bench_ortools -- Google OR-Tools 9.15.6755 SimpleLinearSumAssignment, column "ortools" (paper: OR-Tools)

USAGE
  bench_ortools [--csv] [--tag <text>] <instance.asn>

WHAT IS TIMED
  solver.solve() alone.  The arcs are added one at a time with
  add_arc_with_cost before the clock (the bulk entry point starts a thread
  pool whose spin-down would land inside the first measured window); solve()
  itself builds the library's own graph (ListGraph, FinalizeSetup) from
  them, so that build is inside the clock.  A warm-up solve of an 8x8
  instance precedes the clock so library setup is not timed.  Reading the
  file and reading the cost off the answer are outside.  Clock: process CPU
  time (getrusage).

COLUMNS (one CSV row per run with --csv; without it a human-readable block)

  instance      base name of the .asn file
  nodes, arcs   from its problem line
  left, right   |X| and |Y|
  theta, theta_frac
                always 0 and 0.000: they belong to the export's shortcut and
                are kept so every solver's rows have the same shape
  status        OPTIMAL, NO_PERFECT_MATCHING, or ERROR_<code> / TIMEOUT
  matched       number of matched left vertices (= |X| when OPTIMAL)
  cost          the weight of the matching, minimised
  cpu_ms        THE MEASUREMENT: CPU time between the two clock readings
  cpu_usr_ms, cpu_sys_ms   its user/system split
  wall_ms       wall-clock time over the same window; nothing is derived from it
  tag           free text copied from --tag (the campaign put "<family>;rep=<k>" there)

EXAMPLE (the campaign's raw row)
  low-cost_n2048_s1.asn,2048,22528,1024,1024,0,0.000,OPTIMAL,1024,7920,4.312,4.256,0.056,4.305,low-cost;rep=1

The published raw rows (published_results/hungarian_results.zip,
<column>/<family>.csv) carry two further columns appended by the campaign
runner, inferred_from and core, which the program itself does not print.
