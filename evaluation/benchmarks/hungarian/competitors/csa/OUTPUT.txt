bench_csa -- Goldberg & Kennedy's CSA 1.2, variant csa_q, clock opened before its arc-array pack, column "csa_q_csr" (paper: CSA CSR)

USAGE
  bench_csa [--csv] [--tag <text>] [--timeout <s>] <instance.asn>
  (the launcher fixes --binary build/csa_q; the C program reads the instance
  on standard input and the wrapper feeds it)

WHAT IS TIMED
  Inside the C program (measure.c, added by the patches): the clock starts in
  parse() immediately before CSA packs the arc list it has read into its own
  per-node arc arrays (a counting sort over the complete list; the per-node
  degree counts are redone inside the window), covers CSA's own setup and
  the cost-scaling loop, and stops immediately after that loop.  Reading the
  arc lines and computing the objective (display_results) are outside.
  Clock: CLOCK_PROCESS_CPUTIME_ID; the usr/sys split from getrusage.
  wall_ms is the WHOLE child process including parsing and is not comparable
  with cpu_ms.  The program is compiled with -DMIN_COST (stock CSA negates
  the costs and maximises).

COLUMNS (one CSV row per run with --csv; without it a human-readable block)

  instance      base name of the .asn file
  nodes, arcs   from its problem line
  left, right   |X| and |Y|
  theta, theta_frac
                always 0 and 0.000: they belong to the export's shortcut and
                are kept so every solver's rows have the same shape
  status        OPTIMAL, NO_PERFECT_MATCHING, or ERROR_<code> / TIMEOUT
  matched       number of matched left vertices (= |X| when OPTIMAL)
  cost          the weight of the matching, minimised
  cpu_ms        THE MEASUREMENT: CPU time between the two clock readings
  cpu_usr_ms, cpu_sys_ms   its user/system split
  wall_ms       wall-clock time over the same window; nothing is derived from it
  tag           free text copied from --tag (the campaign put "<family>;rep=<k>" there)
  (status TIMEOUT if the child ran past --timeout; ERROR if its output could
  not be parsed)

EXAMPLE (the campaign's raw row)
  low-cost_n2048_s1.asn,2048,22528,1024,1024,0,0.000,OPTIMAL,1024,7920,2.857,2.390,0.480,12.409,low-cost;rep=1

The published raw rows (published_results/hungarian_results.zip,
<column>/<family>.csv) carry two further columns appended by the campaign
runner, inferred_from and core, which the program itself does not print.
