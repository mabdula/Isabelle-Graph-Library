bench_jgrapht_mwbm -- JGraphT 1.5.3 MaximumWeightBipartiteMatching on SparseIntUndirectedWeightedGraph (CSR) built inside the clock, column "jgrapht_mwbm_csr" (paper: JGraphT MWBM CSR)

USAGE
  [JAVA_HOME=<jdk>] bench_jgrapht_mwbm [--csv] [--tag <text>] <instance.asn>
  (the launcher fixes --solver mwbm)

WHAT IS TIMED
  Construction of the CSR graph (jgrapht-opt's SparseIntUndirectedWeightedGraph,
  immutable, built from the complete edge list), the matcher's constructor
  and getMatching(), all inside the clock; repacking the parsed arrays into
  the List<Triple> the constructor takes is outside.  The matcher MAXIMISES,
  so arcs enter at |X|*cmax + 1 - cost; the large offset forces a
  maximum-cardinality answer, hence the cheapest perfect matching (exact
  BigDecimal sums inside the library; the driver refuses instances whose
  offset weights would leave the exact range of a double).  Warm-up and
  clock as for bench_jgrapht_kuhnmunkres: a seeded random instance until the
  JIT is quiet; thread CPU time plus collector pause time.  JVM flags:
  -XX:ActiveProcessorCount=1 -XX:+UseSerialGC -Xmx24g.

COLUMNS (one CSV row per run with --csv; without it a human-readable block)

  instance      base name of the .asn file
  nodes, arcs   from its problem line
  left, right   |X| and |Y|
  theta, theta_frac
                always 0 and 0.000: they belong to the export's shortcut and
                are kept so every solver's rows have the same shape
  status        OPTIMAL, NO_PERFECT_MATCHING, or ERROR_<code> / TIMEOUT
  matched       number of matched left vertices (= |X| when OPTIMAL)
  cost          the weight of the matching, minimised
  cpu_ms        THE MEASUREMENT: CPU time between the two clock readings
  cpu_usr_ms, cpu_sys_ms   its user/system split
  wall_ms       wall-clock time over the same window; nothing is derived from it
  tag           free text copied from --tag (the campaign put "<family>;rep=<k>" there)

EXAMPLE (the campaign's raw row)
  low-cost_n2048_s1.asn,2048,22528,1024,1024,0,0.000,OPTIMAL,1024,7920,109.860,110.000,-0.140,110.798,low-cost;rep=1

The published raw rows (published_results/hungarian_results.zip,
<column>/<family>.csv) carry two further columns appended by the campaign
runner, inferred_from and core, which the program itself does not print.
