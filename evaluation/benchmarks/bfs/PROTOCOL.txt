HOW ONE MEASURED RUN WAS LAUNCHED -- BFS study
==============================================

Every number in Tables 9 to 12 of the paper is derived from runs launched
exactly as follows.  The benchmark programs in this package print the raw row
of one such run; everything around the program is described here so that a
single run can be repeated under the same conditions.

THE PROBLEM
  A graph file (instances/) plus one (source, target) pair from
  instances/queries.csv, drawn once by instances/generators/draw_queries.py
  (master seed 20261011, the Dijkstra study's; the per-instance seed is
  blake2b("20261011:<file>"), so the Square-n, Long-n and USA-road-t pairs
  are bit-identical to that study's).  Synthetic families: one pair per
  instance.  USA-road-t: ten pairs per network, query ids 0..9.  Every solver
  searches the whole region reachable from the source; the target is only
  looked up afterwards (reached or not), never used to stop early.  Weights
  are parsed and ignored.

THE COMMAND
  taskset -c <core> timeout -k 10 1200 <program> --source <s> --target <t> --query <q> --tag "<family>;rep=<k>" <instance.gr>
  with, for the two Python programs, --mem-gb 45 appended (RLIMIT_AS cap).
  <program> is one of
    bench_sml_csr, bench_sml_rbt, bench_scala_csr, bench_scala_rbt,
    bench_go_csr, bench_go_rbt                               (this directory)
    competitors/lemon/bench_lemon                            column lemon_csr
    competitors/lemon_linked/bench_lemon_linked              column lemon_linked
    competitors/jgrapht/bench_jgrapht                        column jgrapht_csr
    competitors/jgrapht_hashgraph/bench_jgrapht_hashgraph    column jgrapht_hashgraph
    competitors/scipy/bench_scipy                            column scipy_csr
    competitors/scipy_prebuilt/bench_scipy_prebuilt          column scipy_prebuilt
    competitors/networkx/bench_networkx                      column networkx
  The JVM programs are launched through their wrapper, which runs
    java -Xmx45g -XX:ActiveProcessorCount=1 -XX:+UseSerialGC
  so that the JVM sizes nothing for 32 cores and collects on the measured
  thread.

REPEATS AND AGGREGATION
  Three repeats per problem, EACH IN ITS OWN PROCESS (never --repeats 3), so
  no repeat runs on a cache warmed by an earlier one.  The per-problem time is
  the median of the three cpu_ms values; the table cell is the mean of the
  per-problem medians over the ten problems of that size (ten instances, or
  ten queries of one road network), in seconds, and the parenthesised ratio
  is that mean divided by the SML imp. column's mean for the same size.

PINNING
  One run per L3 cache island, seven islands in use (cores 4, 8, 12, 16, 20,
  24, 28 of the 8 x 4-core islands of the machine), the eighth island
  (cores 0-3) reserved for everything that is not a measurement.  Solvers
  were measured one group at a time (sml_csr, sml_rbt; then lemon, jgrapht,
  scipy, networkx; then scala_csr, scala_rbt; then go_csr, go_rbt), each
  group finishing every family, size and repeat before the next started.

CORE WARM-UP
  None in this study: no spin preceded the program.  JVM warm-up inside the
  program: see the OUTPUT.txt of the Scala and JGraphT programs.

TIMEOUT AND LADDER
  1200 s wall per run, then SIGKILL after 10 s.  A timeout is recorded as
  TIMEOUT with empty time columns; the other repeats of that problem and
  every larger size of that (solver, family) are recorded TIMEOUT_INFERRED
  without being run (TO in the paper).  Out of memory likewise (OOM).

WHICH RESULTS DIRECTORY EACH COLUMN COMES FROM (raw rows in
paper_results/bfs_results.zip, <column>/raw/<family>.csv; the ids are the
campaign's results directories, named as provenance)
  sml_csr, sml_rbt, scala_csr, scala_rbt, go_csr, go_rbt, networkx,
  lemon_linked, jgrapht_hashgraph, scipy_prebuilt
                                     20261011_131341
  lemon_csr, jgrapht_csr, scipy_csr  20261014_161905
  sml_csr on USA-road-t.NY           rerun_ny_20261012_101143,
                                     measured with nothing else running on
                                     the machine (mean 39.455 ms).
  lemon_csr, jgrapht_csr and scipy_csr measure the three libraries with their
  CSR structure built inside the clock; the *_linked / *_hashgraph /
  *_prebuilt columns measure them on a structure built outside the clock.
  Both driver versions are in competitors/.

THE CLOCK
  CPU time (user + system) read immediately before and after the solver call.
  Exports: the whole entry point, structure build included (the functional
  exports' arc LIST is consed outside, build_ms).  Libraries: see each
  OUTPUT.txt for what sits inside.  cpu_ms is the only time the tables use.
