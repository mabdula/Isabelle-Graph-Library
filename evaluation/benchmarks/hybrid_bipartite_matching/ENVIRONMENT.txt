MACHINE AND SOFTWARE BEHIND THE NUMBERS OF THE PAPER APPENDIX
=================================================

HARDWARE   Lenovo ThinkSystem SR645, 2 x AMD EPYC 7343 (16 cores each, no SMT,
           32 cores), 8 L3 islands of 4 cores and 32 MiB, 377 GiB RAM, no swap.
           Governor schedutil: idle cores at 1.5 GHz, 3.9 GHz under load.
OS         Ubuntu 22.04.4 LTS, kernel 5.15.0-198-generic, x86_64.

TOOLCHAINS
  MLton   20241230  (bin/mlton md5 9d6e09d40426a5aa72c6851885a3976e); needs gmp.h/libgmp
  gcc     11.4.0 (Ubuntu 11.4.0-1ubuntu1~22.04.3), also MLton's C back end
  Python  3.10.12 (the CSV wrapper and the warm spin use the standard library only)
  awk     GNU Awk 5.1.0 (the twocost.a and geomasn.a filters)
  bash    5.1 (the generation scripts)

THE ORACLE
  CSA 1.2 (Goldberg and Kennedy), precise-costs sources from the DIMACS Flows
  2.0 distribution csa-flows20.tar.gz (md5 e07d8ad4b68bba1096f39eba7cfd7dda),
  as shipped inside the solver's source zip (asn_solver.zip, md5
  12297ed4bcdf50fb819c548947f1c443) with the CSA_LIBRARY changes described in
  code/README_solver.md; built as variant csa_q (-DQUEUE_ORDER -DMIN_COST).

THE EXPORT
  generated_code_used_for_benchmarking/MD5SUM.txt pins Assignment_Solver.sml
  as benchmarked (md5 232e15a004db03c56b5233646e8bc132).  `make check'
  verifies it.
