INSTANCES OF THE HYBRID BIPARTITE MATCHING RUNS -- where every file came from
============================================================================

The same three assignment families as the Hungarian study (DIMACS Flows 2.0
recipe, "Assignment Problem Instances and Generators"), ten generator seeds
per size, extended upward for this solver.  No instance file is distributed;
every one is regenerated by the scripts in generators/ and can be checked
against MD5SUM_instances.txt where a checksum exists.

HOW TO OBTAIN
  Generators  ../setup_instances.sh fetches assign.c, dcube.c, twocost.a and geomasn.a (and the
              depository's readme) from the First DIMACS Challenge depository at
              archive.dimacs.rutgers.edu (URLs and md5 in the script) and makes the
              patched copies that compile today; `make' in generators/ builds them.
  Instances   not distributed: regenerate them with generators/gen_instances.sh and
              gen_geometric.sh for the
              sizes and seeds listed in seeds/<family>.txt and compare with
              MD5SUM_instances.txt.

  low-cost    assign.c: nodes N, sources N/2, degree round(2 log2 N),
              maxcost 100, seed K.  N = 2048 .. 32768 (study grid) and
              65536 .. 1048576 (added for this solver).  m = N log2 N.
  two-cost    the same assign output piped through twocost.a (the arc costs
              become two values); same N and seeds.
  geometric   dcube.c: nodes N, dimension 2, maxloc 1000000, seed K, piped
              through geomasn.a: complete bipartite graphs, cost = truncated
              Euclidean distance, m = (N/2)^2.  N = 256 .. 4096 (study grid)
              and 8192, 16384 (added).
  Seeds K = 1 .. 10 at every size.  seeds/<family>.txt lists every instance
  with its exact generator parameters.

HOW TO REGENERATE
  cd generators && make                      # build/assign, build/dcube
  ./gen_instances.sh --nodes 2048 --seeds 1  # -> ../files/low-cost/, ../files/two-cost/
  ./gen_geometric.sh --nodes 256 --seeds 1   # -> ../files/geometric/
  The scripts are the study's own, with their three path lines made relative
  (noted at their top); they apply the recipe's repairs (twocost.a's banner is
  split off the problem line; geomasn.a's `e' arc lines become `a') and
  validate each file's arc count.  The patched generator sources are made in
  generators/build/ by ../setup_instances.sh, which fetches the pristine files to
  generators/ and applies assign.c.patch and dcube.c.patch; the Makefile
  comment lists what the patches change.  A 16384-node geometric instance is
  1.4 GB; 32768 would have needed 55 GB for ten files and was not run.

CHECKING
  MD5SUM_instances.txt: md5, size and path of the 150 study-grid files
  (seeds 1-10).  No checksum was recorded for the added sizes, so for those
  sizes only the seed and the generator identify the instance.

FORMAT (assignment_format of the challenge)
  p asn <nodes> <arcs>;  n <id> for every left node;  a <l> <r> <cost>.
