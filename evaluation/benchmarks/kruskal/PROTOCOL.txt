HOW ONE MEASURED RUN WAS LAUNCHED -- Kruskal study
==================================================

Every number in Tables 16 to 18 of the paper is derived from runs launched
exactly as follows.  The benchmark programs in this package print the raw row
of one such run; everything around the program is described here so that a
single run can be repeated under the same conditions.

THE PROBLEM
  One graph file (instances/): a minimum spanning forest of the whole graph,
  every arc line taken as an undirected edge of its weight, parallel edges
  collapsed to the cheapest by every program's parser (outside the clock).
  No source, target or query.  instances/problems.csv lists the 300 problems
  (family, instance, nodes, arcs).

THE COMMAND
  taskset -c <core> timeout -k 10 1200 python3 ../run/warm_then_exec.py 3 -- <program> --tag "<family>;rep=<k>" <instance.gr>
  with, for the two Python programs, --mem-gb 45 appended (RLIMIT_AS cap).
  warm_then_exec.py (run/ at the top of evaluation/) narrows the affinity to the one core it
  is on, spins on it for 3 s with a busy loop, then execs the program on
  that core, so the program starts on a core that has been busy.  The spin
  is outside the program and outside every clock it reads; the tag records
  warmcore=3s.
  <program> is one of
    bench_sml, bench_scala, bench_go          (this directory)
    competitors/lemon/bench_lemon             column lemon
    competitors/jgrapht/bench_jgrapht         column jgrapht
    competitors/scipy/bench_scipy             column scipy
    competitors/networkx/bench_networkx       column networkx
  The JVM programs are launched through their wrapper, which runs
    java -Xmx45g -XX:ActiveProcessorCount=1 -XX:+UseSerialGC
  so that the JVM sizes nothing for 32 cores and collects while the measured
  thread waits.  bench_scala needs SCALA_HOME (and optionally JAVA_HOME) in
  the environment; bench_jgrapht optionally JAVA_HOME.

REPEATS AND AGGREGATION
  Three repeats per problem, EACH IN ITS OWN PROCESS (never --repeats 3), so
  no repeat runs on a cache warmed by an earlier one.  The per-problem time is
  the median of the three cpu_ms values; the table cell is the mean of the
  per-problem medians over the ten instances of that size, in seconds, and
  the parenthesised ratio is that mean divided by the SML column's mean for
  the same size.

PINNING
  One run per L3 cache island, seven islands in use (cores 4, 8, 12, 16, 20,
  24, 28 of the 8 x 4-core islands of the machine), the eighth island
  (cores 0-3) reserved for everything that is not a measurement.  Solvers
  were measured one group at a time (sml; then lemon, jgrapht, scipy,
  networkx; then scala, go), each group finishing every family, size and
  repeat before the next started.

TIMEOUT AND LADDER
  1200 s wall per run, then SIGKILL after 10 s.  A timeout is recorded as
  TIMEOUT with empty time columns; the other repeats of that problem and
  every larger size of that (solver, family) are recorded TIMEOUT_INFERRED
  without being run (TO in the paper).  Out of memory likewise.  Of the 6300
  runs: 5637 SOLVED, 52 TIMEOUT, 611 TIMEOUT_INFERRED, nothing else; only the
  scala and go columns stopped (their of_list is quadratic in those targets).

WHICH CAMPAIGN THE COLUMNS COME FROM
  All seven columns: the campaign of 2026-10-15 09:13 to 18:56 (id
  20261015_091344), raw rows in published_results/kruskal_results.zip under
  <column>/raw/<family>.csv, with COLUMNS.txt, README.txt and per-column
  conditions.txt (the runner's record of the conditions above).

THE CLOCK
  CPU time read immediately before and after the solver call: getrusage
  (user + system) for the five native programs; the solver thread's CPU time
  plus the collector's pause time for the two JVM programs.  Exports: the
  whole entry point.  Libraries: see each OUTPUT.txt for what sits inside.
  cpu_ms is the only time the tables use.

THE CROSS-CHECK
  Every row carries tree_edges and tree_weight; the weight of a minimum
  spanning forest is a property of the graph alone, and all seven columns
  agree on it on every instance (AGREEMENT.txt in the published zip).
