INSTANCES OF THE KRUSKAL STUDY -- where every graph came from
=============================================================

Three families (Tables 16, 17, 18 of the paper), the same files the BFS and
DFS studies used.  Nothing is distributed here except checksums; every file
can be regenerated byte for byte with the generators in generators/ and
checked against MD5SUM_instances.txt.

HOW TO OBTAIN
  Generators  ../setup_instances.sh fetches the 9th DIMACS Challenge code suite
              ch9-1.1.tar.gz (md5 96c9761eec9dcd27dfb3711203ee4aa6; the download
              sources are listed in the script) into generators/, extracts the
              challenge's scripts genSquare-n.gr.pl and genLong-n.gr.pl from
              it and applies generators/*.pl.patch, which hold exactly the
              study's edits; `make' in generators/ then builds spgrid.exe and
              sprand.exe.  genDense-n.gr.pl is the study's own script and is
              in generators/.
  Instances   not distributed: regenerate them with the scripts (cd generators
              && perl genSquare-n.gr.pl, ...) or any single one with its exact
              command line in seeds/<family>.txt, and compare with
              MD5SUM_instances.txt.

1. Square-n   square grids, n = 2^10 .. 2^21 (actual n = height*width with
              height = floor(sqrt(2^p)), so odd p give 2025, 8190, ...),
              m ~ 4n arcs, weights uniform in [0, n].  10 instances per size.
2. Long-n     long grids of height 16, n = 2^10 .. 2^21, m ~ 4n, weights in
              [0, n].  10 instances per size.
   Both are produced by the 9th DIMACS Challenge's spgrid generator
   (generators/ch9-1.1.tar.gz, gens/grid/spgrid.c) driven by the challenge's
   own scripts genSquare-n.gr.pl and genLong-n.gr.pl, which differ from the
   challenge's copies in scripts/ of the tarball only in $TRIALS = 10
   instead of 1 and in $GENPROG and $DIR (absolute paths as run; relative
   here, see the comment at the top of each script).
3. Dense-n    random graphs, n = 2^10 .. 2^15, m = n^2/16 arcs, weights in
              [0, n], strongly connected (sprand lays a Hamiltonian cycle on
              a random permutation first).  10 instances per size.  Our own
              family, genDense-n.gr.pl, written in the shape of the
              challenge's scripts around the challenge's own sprand
              (gens/rand/sprand.c), because the challenge ships no dense
              family.

   Every script seeds perl's rand() with 971 and draws one 31-bit seed per
   instance, in order p = START..END, trial 0..9; perl 5.34 on Linux
   (drand48) makes that sequence what it was.  seeds/Square-n.txt,
   seeds/Long-n.txt and seeds/Dense-n.txt list, for every instance, the
   resulting seed and the exact generator command line, e.g.
       spgrid.exe 32 0 1024 32 0 1024 1545908516  > Square-n.10.0.gr
       (width, min weight, max weight, height, min, max, seed)
       sprand.exe 1024 65536 0 1024 1545908516   > Dense-n.10.0.gr
       (nodes, arcs, min weight, max weight, seed)
   The first comment line of each .gr repeats the seed.

   To regenerate: cd generators && make && perl genSquare-n.gr.pl
   (and genLong-n.gr.pl, genDense-n.gr.pl); the files land in
   generators/<family>/.  Dense-n at 2^15 is about 1.3 GB per file.

PROBLEMS  problems.csv: family, instance, nodes, arcs -- the 300 problems.
          A problem is the graph alone: every arc line is an undirected
          edge, parallel edges are collapsed by the parser.  The road
          networks of the path studies are not used (one network per size).

CHECKING  MD5SUM_instances.txt: md5, size and path of all 300 .gr files.
